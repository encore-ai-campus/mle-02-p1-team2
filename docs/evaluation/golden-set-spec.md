# 안전 RAG 평가 세트 제작안

## 목표와 범위

TBM 안전교육 질문 50개와 산업재해 통계 질문 50개를 구성한다. 검색 근거 적합성과 최종 답변 품질은 별도 지표로 기록한다. 자동 검증을 기본으로 하고, 자동으로 해결되지 않는 항목만 예외 목록으로 모은다.

이 문서는 제작 기준이다. 질문과 근거가 아직 연결·검증되지 않은 항목은 확정 골든으로 취급하지 않는다. 자동 점검 통과 항목은 `auto_pass_candidate`, 해결되지 않은 항목은 `deferred`로 관리한다.

## 문항 배분

| 영역 | 유형 | 문항 수 | 평가 요소 |
|---|---|---:|---|
| TBM 안전교육 | 작업별 TBM 작성 | 20 | 작업·장비·환경별 위험, 통제, 작업중지 조건, 비상대응 |
| TBM 안전교육 | 신규·일반 근로자 핵심수칙 | 15 | 작업 전 확인, 접근통제, 보호구, 역할·신호, 이상 시 행동 |
| TBM 안전교육 | 사고사례 교육용 설명 | 15 | 사고 흐름, 원인·위험요인, 재발방지 행동, 쉬운 표현 |
| 산업재해 통계 | 업종·규모별 지표 조회와 비교 | 20 | 기준연도, 업종분류, 규모, 지표·단위 |
| 산업재해 통계 | 건수·비율·순위 비교 | 15 | 분자·분모, 비교집단, 단위, 반올림 규칙 |
| 산업재해 통계 | 기간별 추세 | 10 | 시작·종료 연도, 자료 범위, 추세 해석의 한계 |
| 산업재해 통계 | 사고유형 통계 (근거 확보 대기) | 5 | 출처·분모가 없으면 답변 보류를 정답으로 처리 |

TBM은 크레인 인양, 고소작업, 굴착, 화기작업, 밀폐공간 등 서로 다른 작업에 분산한다. 통계는 한 업종이나 사고유형에 편중되지 않게 하되, 자료에 없는 조합은 질문으로 확정하지 않는다.

## 근거 사용 기준

- 모든 항목에 문서 ID, 사례 ID 또는 통계 파일·행/분류를 연결한다.
- TBM 기준은 출처에 명시된 위험과 예방대책을 중심으로 작성한다. 출처에 없는 법적 의무나 작업중지 기준을 추정해 필수 답변으로 만들지 않는다.
- 통계 문항은 기준연도, 지표, 단위, 분모, 업종분류를 고정한다. 비중은 분자·분모가 모두 확인될 때만 채점한다.
- 단일 연도 자료로 시계열 추세를 묻지 않는다. 업종분류가 없는 시계열 자료로 업종별 추세를 묻지 않는다.
- 근거가 없거나 기준을 정할 수 없는 항목은 답을 만들지 않고 예외 목록에 보낸다.

현재 데이터 안내에 기록된 산업별 통계는 2025년 업종·사업장 규모별 재해자 수, 사망자 수, 사업장 수, 사망만인율이다. 규모별 장기 추세 자료에는 업종 분류가 없다. 확인된 자료 목록에는 추락·끼임 등 사고유형별 건수/비중이 없어, 해당 질문은 원 출처가 확보될 때까지 `source_needed`로 둔다.

## 자동 검증과 예외 처리

자동 검증은 필수 필드·ID·중복, 근거 ID/URL, TBM 체크리스트 누락, 통계 기준연도·지표·단위·분모·분류, 원자료와 수치의 일치, 계산·반올림, 출처에 없는 주장을 확인한다.

검증 실패는 오류 코드와 근거를 기록한 뒤 자동 수정·재검증을 최대 2회 시도한다. 같은 오류가 남거나 출처가 없거나 복수 해석이 가능하면 `deferred`로 전환하고 반복 수정을 멈춘다. 예외 목록에는 질문 ID, 오류, 확인한 근거, 시도 횟수, 필요한 해결 조치를 기록한다.

사람 검토는 전체 승인 절차로 두지 않고 해결이 필요한 예외만 별도 보고한다. 자동 통과 항목은 사람 검증 전까지 `auto_pass_candidate`로 표기하며 `human_gold`로 표시하지 않는다.

## 평가 방법

- **검색 근거 적합도:** 기대 근거 검색 여부를 Hit@k/MRR로 평가하고 관련성은 질문-근거 쌍 단위로 기록한다.
- **답변 품질:** 필수 요소 충족, 수치·출처 일치, 무근거 주장 여부를 별도 평가한다.
- **TBM 안전성:** 위험요인·통제 행동·작업중지·비상대응과 출처 일치를 확인한다.
- **통계 정확성:** 숫자·단위·분모·기간·업종분류·출처를 각각 대조한다.
- 자동 판정과 사람 판정은 구분해서 보고한다.

## 골든 승인과 평가 결과 분리

- 자동 검증 통과는 후보 통과이며 `human_gold` 승인이 아니다. 골든으로 승격하려면 기대 근거, 기준 답변 또는 필수 답변 요소, 채점 기준이 모두 연결되어야 한다.
- 검색 평가에서는 질문별 기대 근거와 관련성 판단을 확정한다. 답변 평가는 기준 답변 또는 채점 가능한 필수 요소를 별도로 확정한다.
- 최종 결과는 자동 검증과 사람 검증을 구분하고, 검색 실패와 답변 오류를 따로 집계한다. 한 지표의 통과를 다른 지표의 통과로 간주하지 않는다.
- TBM 항목은 근거와의 일치뿐 아니라 위험한 누락, 실행 불가능하거나 잘못된 작업 지시, 출처에 없는 법적 단정 여부를 안전성 예외로 확인한다. 전체 수동 승인 대신 해당 예외와 표본 점검 결과를 보고한다.

## 예외 종료 기준

- 예외 레코드에는 해결에 필요한 원자료, 기준 결정 또는 사람 판단을 구체적으로 적는다.
- 같은 오류를 반복 수정해도 새 근거가 생기지 않으면 추가 시도를 멈추고 `deferred`로 종료한다. 근거가 확보되지 않은 상태에서 질문·정답을 추정해 채우지 않는다.
- 재개는 필요한 근거 또는 기준이 확보된 경우에만 한다. 해결 전까지 예외 건수와 평가에서 제외된 이유를 결과에 남긴다.

## 문항 레코드

`question_id`, `category`, `task_type`, `question`, `constraints`, `evidence_ids`, `expected_points`, `answer_checks`, `status`, `issue_code`, `issue_note`, `validation_attempts`, `review_provenance`를 저장한다. 상태는 `draft`, `source_needed`, `auto_pass_candidate`, `human_review_needed`, `deferred`를 사용한다.

## 완료 보고

영역별 전체 수와 상태별 통과·보류·근거부족 수를 보고한다. 예외는 오류 유형별 건수와 질문 ID를 묶는다. 자동 검증 통과를 사람 검증 완료나 현장 안전 승인으로 표현하지 않는다.

## 후보 세트 생성

`python scripts/generate_golden_candidates.py --source-root <로컬 RAG-project 경로>`로 후보 100개와 예외 큐를 생성한다. 출력은 Git 제외 대상인 data/evaluation/에 기록하며, 자동 생성 결과는 사람 확정 골든이 아니다.
