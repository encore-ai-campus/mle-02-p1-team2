# 골든셋 7·8번 작성 및 최종 검토

담당 범위는 ⑦ TBM·안전교육과 ⑧ 산업재해 통계다. 프로젝트 자료에 근거한 문항·기준 답변과 검색 후보 판정 초안을 준비하고, 최종 사람 검토와 팀 기준 합의 후 확정 평가에 사용한다.

## 로컬 산출물

평가 데이터는 저장소 공개 범위 원칙에 따라 Git에서 제외된 data/evaluation/golden_set_78/에 보관한다. 골든셋 본문은 golden_set_78.md, 구조화 원본은 golden_set_78.jsonl이다. 후보 원문·판정 초안은 candidate_review_78.csv와 동일 이름의 JSONL, 문항별 최종 검토 입력란은 human_review_checklist_78.csv다. ZIP 묶음과 출처 점검·계산·검증 보고서도 같은 폴더에 있다.

골든셋은 id/category/sub_category/user_type/question/gold_answer/evidence/source/keywords/difficulty/note의 11개 필드를 유지한다. note에는 기대 행동, 포함할 핵심 내용과 허용하지 않을 추론을 기록한다.

## 최종 검토

1. 문항별 evidence와 source로 원자료를 다시 찾고 기준 답변을 확인한다.
2. 후보의 장비·작업·위험·적용 조건 또는 통계의 지표·연도·대상을 비교해 관련성을 판정한다.
3. AI 초안과 별도인 human_label/human_reason/reviewer/reviewed_on을 작성한다.
4. 애매 사례의 결정 이유와 팀 합의한 판정 기준 버전·날짜를 기록한다.
5. 답변·출처·후보 검토와 팀 합의가 모두 끝난 항목만 final_ready=true로 변경한다.

| 판정 | 원칙 |
| --- | --- |
| 관련 | 핵심 조건이 일치하고 핵심 주장에 직접 사용할 충분한 근거가 있다. |
| 부분관련 | 일부 조건만 맞거나 보조 근거만 제공한다. |
| 비관련 | 핵심 작업·장비·지표·기간·대상이 다르다. |
| 애매 사례 | 임의 관련 판정을 피하고 별도 표시·팀 검토·결정 이유를 기록한다. |

다중 근거 문항에서는 후보 1건의 관련성과 전체 답변의 충분성을 구분한다. 특정 사고 설명 문항은 시트·연번이 일치해야 한다. 자료 범위 감사는 자료 부족을 확인하는 근거이며 없는 통계의 실측 정답을 제공하지 않는다.

## 검색·답변 평가에서 지킬 조건

오프라인 BM25 후보는 실제 앱의 pgvector 순위나 LLM 재정렬 결과와 구분한다. 실제 검색된 후보에만 rank를 부여한다. 검색에서 빠진 직접 근거인 curated_source와 자료 범위 점검인 source_audit는 검색 순위 지표에 넣지 않는다.

통계는 정형 데이터 경로로 평가하며 SIF 사례 빈도를 전국 사고 통계로 일반화하지 않는다. 원자료가 제공하지 않는 사고 유형별 수치, 근로자수 분모, 결측 연도를 추정해 정답으로 채우지 않는다. 지표·열 제목 충돌이나 OCR 섹션 불일치는 출처 점검에 기록하고 확정 전에 해결한다.

사람 검토와 팀 합의 전에는 초안 라벨을 정답 라벨로 자동 승격하거나 Hit@k·MRR 등을 확정 성능으로 보고하지 않는다. 비교할 때는 질문·코퍼스·판정 기준 버전을 고정한다.

## 공개 범위

이 문서는 검토 절차를 공유한다. 원본 데이터, 파생 평가 데이터, 후보 원문, 자격 증명은 포함하지 않는다. 로컬 평가 산출물의 별도 공개는 저장소의 데이터 공개 승인 원칙을 따른다.
