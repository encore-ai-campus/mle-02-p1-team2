# 벡터 DB 적재 로그

작성: 송수림 · 2026-10-07 · 근거: `notebooks/su-lim/04_m4_벡터DB적재.ipynb`(인덱싱 코드)와 로컬 ChromaDB(`data/chroma/chroma.sqlite3`)를 읽기 전용으로 직접 조회한 값

## 1. 이 문서가 무엇인가

- 인덱싱 코드는 `04_m4_벡터DB적재.ipynb`에 있다.
- 처음 적재할 때 찍힌 진행 로그(50개씩 적재하는 과정)는 보존되어 있지 않다. 이 노트북은 "이미 들어 있는 문서는 건너뛰고 없는 것만 적재"하도록 만들어져 있어서, 이후 다시 실행한 기록(새로 적재할 문서 0건)만 남았다.
- 그래서 이 문서는 **지금 DB에 실제로 들어 있는 상태**를 직접 조회한 결과로 적재가 정확히 끝났는지 확인한다. 아래 숫자는 DB에서 읽은 값이다.

## 2. 적재 설정

| 항목 | 값 |
|---|---|
| 문서 구성 | 사례 1건 = 문서 1개 (청킹하지 않음. 문서 평균 372자, 최대 817자) |
| 문서 본문에 넣은 것 | 업종 분류, 고위험작업(제조업등) 또는 재해종류(건설업), 재해개요, 기인물, 재해유발요인, 예방대책 |
| 메타데이터(필터 검색용) | 업종구분, 중분류, 기인물, 재해종류, 재해연도 |
| 임베딩 모델 | `text-embedding-3-small` (차원 1,536), 문서당 6,000자까지 사용 |
| 벡터 DB | ChromaDB `PersistentClient`, 거리: 코사인 (`hnsw:space = cosine`) |
| 적재 단위 | 50개씩 묶어 임베딩 후 적재, 중간에 멈춰도 다시 실행하면 이어서 적재 |

## 3. 적재 결과 (DB 직접 조회)

| 컬렉션 | 문서 수 | 임베딩 차원 | 구성 |
|---|---|---|---|
| `sif` | 6,032 | 1,536 | 제조업등 2,573 + 건설업 3,459 (RAG 기본 컬렉션) |
| `sif_v2` | 6,042 | 1,536 | `sif` + 통계 10 (M7 1차 개선) |
| `sif_v3` | 6,252 | 1,536 | `sif` + 통계 220 (M7 2차 개선, 규모×연도) |

확인한 점:

- 원본 사례 수와 일치한다. 처리된 사례 6,032건(제조업등 2,573 + 건설업 3,459)이 `sif`에 빠짐없이 들어 있다.
- 세 컬렉션 모두 메타데이터 `업종구분`이 비어 있지 않고, 업종별 문서 수가 위 구성과 정확히 맞는다.
- 메타데이터 키는 `업종구분`, `중분류`, `기인물`, `재해종류`, `재해연도` 다섯 개다.
- 컬렉션을 새로 만들 때 `sif`의 문서와 임베딩을 그대로 복사하고 통계 문서만 추가했다. 개선 전 컬렉션은 그대로 보존했다.

## 4. 적재 후 검색 확인 (04 노트북 4절)

질문을 임베딩해서 가까운 사례 3건을 찾고, 점수는 `1 - 코사인 거리`(클수록 비슷)로 확인했다.

| 질문 | 필터 | 상위 3건 점수 | 확인 |
|---|---|---|---|
| 지게차 작업 중 협착 사고 원인과 대책 | 없음 | 0.566, 0.557, 0.551 | 3건 모두 제조업등, 기인물 지게차 |
| 비계에서 추락한 사고 | 업종구분 = 건설업 | 0.495, 0.488, 0.487 | 3건 모두 건설업, 기인물 비계·작업발판 |
| 컨베이어에 끼인 사고 | 재해연도 2020 이후 | 0.457, 0.443, … | 제조업등, 기인물 컨베이어 |

질문과 관련 있는 기인물의 사례가 상위에 올라오고, 업종·연도 필터가 검색 범위를 정확히 좁힌다.
