# 08. M8 Streamlit 앱 설명 노트 (코드 리뷰 대비)

파일: `app/su-lim/08_app.py` · 실행: `streamlit run app/su-lim/08_app.py`

**한 줄 요약** 왼쪽 사이드바 필터(업종·연도·k)를 두 탭이 같이 쓴다. **대시보드** 탭은 M2·M3 데이터로 지표 4개와 차트 4개를 그리고, **챗봇** 탭은 05의 RAG 체인(검색 → 사례만 근거로 답변 → 출처 표시)을 그대로 쓴다.

## 코드 순서

| 구역 | 하는 일 | 05/03과의 관계 |
|---|---|---|
| 0. 페이지 설정 | 제목·넓은 화면 | - |
| 1. 프로젝트 폴더 찾기 | `app.py` 위치에서 위로 올라가며 `data/processed`가 있는 폴더를 찾음 | 노트북의 `ROOT` 탐색과 같은 방식 |
| 2. 데이터 읽기 | 사례 6,032건, 규모별 사망자(3번 파일), 사업장당 재해자(M3 결과). `@st.cache_data`로 한 번만 읽음 | 03 노트북 데이터 |
| 3. 사이드바 | 업종 / 재해 연도 / 근거 사례 수 k | 05의 `K`, `where=` |
| 4. 대시보드 | 지표 4개 + 차트 4개, 모두 필터를 따라 바뀜 | 03 분석 |
| 5. 챗봇 | `retrieve → build_prompt → ask`, 근거 부족 처리, 출처 카드 | 05 그대로 |

## 대시보드

- **지표 4개**: 분석 사례 수 / 선택한 끝 연도의 사고사망자 / 가장 많은 기인물(비중) / 시작→끝 연도 사망자 변화율
- **차트 4개**: 연도별 사례 수(업종별 색) · 기인물 상위 10(분류 불가 제외) · 규모별 사고사망자(선택 기간 합계) · 규모별 사업장 1,000곳당 재해자수
- 사례 통계는 업종 필터를 따르지만, **사망자 통계(3번 파일)는 업종 구분이 없어서** 연도 필터만 따른다. 차트 아래 캡션에 적어 둠.
- 사업장당 재해자수는 M3에서 계산한 전체 기간 값이라 필터와 무관하다.

## 챗봇

1. **컬렉션 선택**: `sif_v3` → `sif_v2` → `sif` 순서로 있는 것을 쓴다. 07에서 만든 통계 개선본(v3)이 있으면 자동으로 사용한다.
2. **필터 → `where`**: 업종을 고르면 `{"업종구분": ...}`, 연도를 좁히면 `재해연도 $gte/$lte`를 `$and`로 묶는다. 연도 전체를 선택하면 연도 조건은 걸지 않는다.
3. **근거 기준**: 유사도 `MIN_SIM = 0.40` 미만은 버린다(05 5-1절: 범위 밖 최고 0.353 < 0.40 < 범위 안 최저 0.438). 남은 사례가 없으면 LLM을 부르지 않고 "제공된 사례에서 근거를 찾을 수 없습니다."를 보여준다.
4. **통계 질문**: 프롬프트에 "[통계] 자료는 표의 숫자를 그대로 인용"을 추가했다. 통계 문서는 업종구분이 `통계`라서 **업종을 '전체'로 둘 때만** 검색된다.
5. **오류 처리**: API 오류는 화면에 빨간 메시지로 보여주고 앱은 계속 동작. `.env`에 키가 없으면 챗봇 탭에만 경고를 띄우고 대시보드는 쓸 수 있다.
6. **예시 버튼**: 누르면 질문칸이 채워지고 바로 실행된다(`on_click` 콜백).

## 예상 질문과 답

- **Q. 왜 ipynb가 아니라 py인가?** Streamlit은 `streamlit run app.py`로 서버를 띄워 브라우저에 보여주는 방식이라 스크립트 파일이어야 한다. 설명은 이 노트로 대신한다.
- **Q. 05 코드를 왜 다시 썼나?** 앱은 노트북을 import할 수 없어서 `retrieve / build_prompt / ask`를 그대로 옮겼다. 로직은 같고 `.get()`으로 통계 문서의 빈 메타데이터도 처리하게만 바꿨다.
- **Q. 필터가 챗봇에도 적용되나?** 그렇다. 사이드바 업종·연도·k가 ChromaDB `where`와 검색 개수에 들어간다.
- **Q. 매번 다시 읽지 않나?** `@st.cache_data`(CSV)와 `@st.cache_resource`(OpenAI 클라이언트·ChromaDB)로 한 번만 만든다. Streamlit은 버튼을 누를 때마다 스크립트 전체를 다시 실행하기 때문에 필요하다.
- **Q. 왜 건설업을 고르면 통계 질문이 안 되나?** 통계 문서에는 업종 구분이 없고 별도 값(`통계`)이라서, 업종 필터가 걸리면 검색 대상에서 빠진다. 한계로 기록해 둔다.
- **Q. 한계는?** 현장 말투 질문의 검색 정확도(Hit@5 0.26)는 M7 이후에도 그대로이고, 그 문제가 앱에서도 그대로 보인다. 다음 개선 후보는 질문 앞부분 정리와 기인물 필터 추출이다.
