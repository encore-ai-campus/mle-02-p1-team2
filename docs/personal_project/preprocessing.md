## ②~⑤ 업종×규모 전처리

| 대상 | 처리·검증 | 남겨 둔 값과 이유 |
| --- | --- | --- |
| ②~⑤ CP949 CSV | 각 30행·업종 2열·규모 10열을 확인했다. 범주 이름의 NFKC와 공백만 통일한 뒤 각 300칸으로 펼쳤고, 동일 업종×규모 키 300개가 일대일로 결합됐다. 원본 파일 4개 SHA-256과 가공본 수치 1,200칸을 독립 대조했다. | 원본 값 불일치 0칸. 범주 정리 후 키 충돌 0건. 기간 표시는 포털 파일명 `_20251231`에서 확인했다. |
| ⑤ 결측 | 공란 14칸을 결측으로 유지했다. | 포털은 공란을 재해율 산출 불가로 설명한다. 0으로 대체하면 실제 0과 구별할 수 없다. |
| 자료 간 수치 차이 | ③ 사고사망자 0명인데 ⑤ 사망만인율 양수인 칸 70개, ⑤가 1,000 초과인 칸 8개, ④ 사업장 0개소인데 ② 사고재해자 1명인 칸 1개를 별도 표시했다. | 네 원본과 API 스냅샷 값이 가공본과 일치한다. ⑤는 임금근로자 1만 명당 사망자 비율이고 ③은 사고사망자 수이므로 동일 분자를 전제하지 않는다. 희소 업종·규모의 극단값도 원인 확인 전 삭제하지 않는다. |

④ 사업장 수는 ⑤의 임금근로자 수 분모가 아니다. 특히 사업장 수 0개소인 셀은 사업장당 사고율 계산 대상에서 제외한다. 집계 셀의 사고재해자 수와 사업장 수 사이 상관은 위험률이나 인과효과가 아니다. 실행 기록은 `notebooks/personal/M2_전처리/02b_...`와 개인 `data/personal/reports/dashboard_preprocessing.json`에 있다.

## RAG 입력과 검색 범위

① 사례는 원문 문장을 보존하고 출처 ID를 붙인다. ⑥의 CSV 5행은 링크 목록이라 본문에 넣지 않고 실제 보고서 PDF 3개를 사용한다. ⑧은 지침 PDF 18개다. 전체 578쪽에서 처음 텍스트가 80자 미만이었던 105쪽을 한국어 RapidOCR로 처리했다. 신뢰도 0.75 미만 줄을 빼고 80자 이상 남은 99쪽은 750자 청크·100자 겹침으로 색인했고 6쪽은 제외했다. PDF 쪽 번호와 OCR 사용 여부를 청크 메타데이터에 저장한다. `A-G-2-2025` 19쪽도 OCR 텍스트가 검색에 들어갔지만 자동 인식 내용은 원문 대조가 필요하다.

개인 Chroma에는 문자 n-gram 기준선과 OpenAI 의미 임베딩 색인을 따로 둔다. 고정한 다자료 질문 21개를 전체 자료와 자료 유형 필터로 평가한다. 질문 수가 적어 전체 현장 검색이나 답변 정확도를 보증하지 않는다. ⑦ 용어사전 확장 실험 10문항도 지침 검색 범위로만 해석한다.

OCR 처리 뒤에도 80자 미만으로 남은 6쪽을 2026-10-03에 전수 확인했다. 다섯 쪽은 PDF 표지이고, M-155-2023 PDF 20쪽은 ‘일일 점검표’ 구분 페이지다. 점검표 본문은 21쪽(인쇄 쪽수 18)에 색인되어 있고, 자료 유형을 KOSHA GUIDE로 제한한 문자 검색에서 상위 3위로 검색되는 것을 확인했다. 상세 목록과 검증 질의는 data/personal/reports/ocr_excluded_page_review.md에 기록했다. 따라서 이 6쪽은 본문 누락이 확인된 페이지가 아니라 표지·구분 페이지라 검색에서 제외한 것이다.

PDF 텍스트 추출은 **글자 수가 충분해도 수치와 글자 순서가 바뀔 수 있다**. `A-G-4-2025` 7쪽에서는 원문 추출 결과가 `개 이상의 버팀대 ... 이동3\n식`처럼 분리됐다. 생성 답변에서 `개 이상의 버팀대`처럼 숫자가 빠진 문장이 실제로 나왔다. 인용 번호만 검증해서는 이를 막지 못하므로 인용 없는 목록 항목과 이 형태의 누락 수량을 답변에서 거절하도록 했다. 다른 문서의 수량·규정 문장까지 완전 검증된 것은 아니며, OCR 및 원문 페이지 대조와 답변 평가가 필요하다.
