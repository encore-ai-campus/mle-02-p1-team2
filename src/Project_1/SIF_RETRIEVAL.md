# SIF 검색 후보 구성

## 범위

Preventra와 기존 앱이 공유하는 SIF 검색 경로를 개선합니다. 공개 서비스 함수의
인자와 반환 타입은 유지합니다. KOSHA의 질문 분석·필터·재정렬·수록 자료는
이번 변경 범위에서 제외합니다. Agent, UI, 통계, 대화 저장, Langfuse 설정은 유지합니다.

## 처리 흐름

1. `services/sif_retrieval.py`에서 SIF 검색문을 준비합니다. 요청을 설명하는
   일반 표현을 제거하고 업종·설비·재료·작업·사고유형 표현을 남깁니다.
   검색 대상의 허용 목록과 앞 6개 단어 제한은 사용하지 않습니다.
   원래 검색문은 최종 재정렬에서 부정 표현과 복합 조건을 판단할 때 사용합니다.
2. 기존 임베딩 모델로 위 검색문을 임베딩합니다. 일반 사고 용어를 추가하지 않습니다.
3. 두 검색 경로를 실행합니다.
   - 키워드: 사고 원문과 기인물·업종·작업 분류 등 의미 필드를 검색합니다.
     출처 파일명·시트명·행 번호는 검색 대상에서 제외합니다. 단어별 문서 빈도를
     계산해 희소한 표현의 일치를 우선합니다. 이 점수는 IDF 기반이며 BM25는 아닙니다.
   - 벡터: SIF 전체에서 의미상 가까운 후보를 찾습니다. 고정 장비·사고유형
     목록에 따른 metadata 필터로 후보를 제외하지 않습니다.
4. 각 경로 최대 10건의 **합집합 전체(최대 20건)**를 중복 제거합니다.
   RRF 점수는 후보 순서와 재정렬 장애 시 대체 순위를 정합니다.
   한 경로가 먼저 10건을 채웠다는 이유로 다른 경로를 자르지 않습니다.
5. 기존 LLM 재정렬에 사고 본문·업종과 원래 검색문을 전달합니다.
   관련성 점수 30 이상에서 최대 3건을 반환하며, 후보가 3건 이하라도 평가합니다.
   Agent는 이번 턴에서 실제 채택한 근거만 인용하고 UI에 전달합니다.

`sif_search`, `sif_keyword_search`, `retrieve_sif` 인터페이스는 같습니다.
직접 SQL 필터를 사용하는 외부 호출과의 호환성을 위해 기존 필터 helper는
남겨두되, `retrieve_sif`에서는 고정 필터를 사용하지 않습니다.

## 오프라인 회귀 검사

저장소 루트에서 설치된 환경의 Python으로 실행합니다.

```bash
PYTHONPATH=src/Project_1 python -m unittest discover -s apps/accident_assistant/tests -v
PYTHONPATH=src/Project_1 python -m unittest discover -s src/Project_1/tests -v
```

합성 자료로 출처 오매칭 방지, 미등록 단어·뒤쪽 검색 대상 보존, 사고유형 필터
미적용, 두 후보군 합집합, 중복 제거, 재정렬 장애 처리와 KOSHA 기존 동작을 검사합니다.

## 실제 평가

Supabase와 OpenAI 설정이 필요합니다. `--live`는 유료 API에 질문·검색 근거를
보내는 명시적 실행 옵션입니다. 설정된 기존 Langfuse tracing도 적용됩니다.

```bash
PYTHONPATH=src/Project_1 python apps/accident_assistant/tests/evaluate_sif_live.py \
  --live --output /tmp/preventra-sif-evaluation.jsonl
```

제지·제지 끼임·제지 롤러·종이 제조·인쇄기·혼합기·섬유·도금·지게차·굴착기
질문 10개와 2턴 후속 대화를 `preventra_ui.gateway.dispatch`로 실행합니다.
원문 질문, Agent 검색문, 키워드·벡터 후보, 재정렬 결과, 최종 인용을 기록합니다.
대화 DB나 원자료는 쓰지 않습니다. 출처 발췌를 담은 결과 파일은 저장소 밖에서만
생성하며 기존 파일을 덮어쓰지 않습니다.

실행 성공과 결과 건수만으로 품질 통과를 판정하지 않습니다. 기록된 실제 근거와
답변을 대조해 작업 대상·사고유형 일치, 타 업종 참고 사례의 명시, 출처 인용을
검토해야 합니다. 전체 정답 문서 집합을 라벨링한 평가가 아니므로 이 진단 결과를
코퍼스 전체 Recall@k·정확도로 표현하지 않습니다.

## 한계

- 조사 제거는 보수적인 문자열 처리입니다. 형태소 분석이나 모든 동의어 해석을 보장하지 않습니다.
- 수록되지 않은 자료는 반환할 수 없습니다. KOSHA의 기존 자료 범위와 검색 한계는 그대로입니다.
- 최대 재정렬 후보가 10건에서 20건으로 늘어 입력 토큰과 처리 시간이 증가할 수 있습니다.
- 재정렬과 최종 채택에는 모델 변동성이 있습니다. 소수 진단 질문의 통과가 모든 질문의 품질을 보장하지 않습니다.
